# План разработки музыкального приложения

Слушатель устанавливает нативное приложение на Rust для Windows, регистрируется, находит полную запись и запускает персональную волну. Один VPS обслуживает аккаунты, поиск, плейлисты и рекомендации. Музыка появляется из внешних каталогов автоматически. Android отложен до следующего этапа, iOS — на будущее.

## 1. Проверить источники и версии записей

Для первой проверки пользователь выбрал порядок Hitmo → SoundCloud. У HomeMusic основной поиск дискографий использует Deezer, а Hitmo и SoundCloud участвуют в поиске записей. Приоритет источника применяется только между совпадающими версиями, доступными для нужного способа воспроизведения.

Собрать контрольный список из 50 записей, включив русскоязычные и зарубежные треки, свежие релизы, пары Explicit/Clean, ремиксы и одноимённые песни. Для каждого результата записать источник, исполнителя, название, длительность, версию, время поиска и доступность полного потока в публичном стороннем клиенте. Проверять попадания на конкретных записях. Отдельно считать долю полных совпадений и ошибочных подмен.

Для Hitmo проверить документированный доступ, условия показа и воспроизведения. У SoundCloud стандартные условия ограничивают совместную очередь с музыкой других платформ. Доступность файла на сайте и статус playable сами по себе не разрешают такую интеграцию. До подтверждения условий использовать собственные тестовые записи для проверки плеера. Оставить переход к странице источника отдельным действием. В волну включать только записи с доступным полным воспроизведением.

Источники — [HomeMusic](https://github.com/justman-1/HomeMusic-public/blob/master/hub/API.md), [конфигурация HomeMusic](https://github.com/justman-1/HomeMusic-public/blob/master/config.example.yaml), [SoundCloud API](https://developers.soundcloud.com/docs/api/guide.html), [условия SoundCloud](https://developers.soundcloud.com/docs/api/terms-of-use).

## 2. Подготовить VPS

Домен сервиса — `primecloud.pigboss.xyz`. Перед установкой проверить ОС, vCPU, RAM, диск, занятые порты и существующий HTTPS-прокси. Разместить API на внутреннем порту за HTTPS, базу открыть только приложению. Выделить непривилегированную учётную запись службы. Настроить резервную копию пользовательских данных и проверить восстановление.

## 3. Провести один трек от поиска до колонок и наушников

Стек первой сборки — Rust, Win32, Windows Media Playback, сервер на Python и SQLite. Сервер отвечает за аккаунты и данные каталога, клиент управляет очередью, буфером и звуком. Разделить запись и её конкретные версии. Сохранять источник и степень уверенности в отметке Explicit. Предпочитать оригинал, показывать сомнительные совпадения отдельно.

Первый работающий сценарий — вход, поиск, полное воспроизведение, пауза, перемотка и избранное на Windows. Проверить сохранение входа через Telegram, восстановление очереди и автообновление через GitHub Releases. Замерить холодный запуск, память и время до первого звука.

## 4. Автоматизировать новинки и персональную волну

Получать новые публикации доступных источников по расписанию, различать дату выхода и дату перезалива, обновлять доступность и убирать дубли. Проверить, что сингл появился в профиле артиста без ручной загрузки.

Новому слушателю предложить старт от трека или артиста. Для следующей очереди смешивать музыку знакомых исполнителей, похожие треки и новинки. Лайк, явное «меньше такого» и пропуск учитывать с разным весом. Убирать повторы и недоступные записи до выдачи очереди. Измерять ранние пропуски и долю открытий, к которым человек вернулся самостоятельно.

## 5. Выпустить закрытую бету

Выпустить Windows-клиент через GitHub Releases. Проверить регистрацию с чистого устройства, параллельное прослушивание, отказ одного источника и сохранение плейлистов после обновления. Перед публичным запуском сверить покрытие каталога, доступность оригинальных версий, расход трафика и стабильность фонового воспроизведения по данным беты.
